# Corset-tools

Companion tools for working with transcript clusters generated by
[Corset](https://github.com/Oshlack/Corset) (Davidson and Oshlack, 2014).

All four helper tools are now subcommands of a single `corset-tools` entry point:

| Subcommand      | Purpose                                                                                              |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| `fetch-seqs`    | Extract transcripts belonging to clusters of interest, tagged with their cluster ID.                 |
| `cross-count`   | Count how many members of each cluster came from each of two transcriptomes.                         |
| `dist-calc`     | Measure the distance between matched transcript pairs and advise on a Bowtie2 `--score-min` setting. |
| `edger-summary` | Filter, annotate and report differentially expressed clusters from an edgeR `topTags` table.         |

Run `corset-tools --help`, or `corset-tools <subcommand> --help`, for the full
option list at any time.

## Installation

From a clone, for development:

```bash
git clone https://github.com/Adamtaranto/Corset-tools.git
cd Corset-tools
pip install -e ".[dev,test]"
```

Requires Python 3.10 or newer.

## Global options

These come _before_ the subcommand:

```code
-V, --version   Print the installed version and exit.
--loglevel      Console verbosity: DEBUG, INFO, WARNING, ERROR or CRITICAL. Default: INFO.
--logfile       Also write logs to this file.
-h, --help      Show help message and exit.
```

## Fetch Cluster Sequences

Given a list of clusters of interest, a transcript fasta, and a Corset mapping
file, `corset-tools fetch-seqs` returns a fasta file of transcripts belonging to
those clusters, renamed as `<clusterID>_<transcriptID>`.

This is intended for use after differential expression analysis, to extract and
annotate the transcripts belonging to DE clusters.

Clusters named in the target list but missing from the map, and cluster members
missing from the fasta, are written to a `NotFound_*.log` file rather than
stopping the run.

### Usage

```bash
corset-tools fetch-seqs \
  -i transcripts.fa \
  -t myfavClusters.txt \
  -c clusters.txt \
  -o transcriptsWithClusterTags.fa
```

### Options

```code
-i, --inFasta       Multi fasta to extract a subset from.

-t, --targetClust   File with target cluster names, one per line. The first
                    whitespace-delimited field of each line is used, so extra
                    annotation columns are ignored. Lines starting with '#' are
                    skipped. If omitted, all clusters are reported.

-c, --clustMap      Corset transcript-to-cluster mapping file. Columns may be
                    separated by tabs or spaces.

-o, --outFasta      Output fasta path. Default: filtered_seqs.fa

-l, --longest       If set, report only the longest transcript per cluster.

--notFoundLog       Path for the unresolved cluster/transcript log.
                    Default: NotFound_<target list>.log

--width             Fasta line wrap width. Default: 80

-h, --help          Show help message and exit.
```

## Cross Cluster Counter

When using Corset to cluster transcriptomes from two
species/isolates/cultivars/etc., sequence variation is likely to exist between
transcriptomes and it is important to check that your Corset clustering has not
excessively split clusters based on transcriptome set.

`corset-tools cross-count` takes a Corset cluster mapping (transcript → cluster)
along with the fasta files for those transcriptomes, and calculates the number
of members from each source transcriptome in each cluster.

Beware of clusters that only contain transcripts from one transcript set when
running differential expression analyses — these may create a false
differential expression signal.

If you have many clusters in which reads from only one transcriptome set are
present, consider adjusting your `--score-min` threshold in `Bowtie2` to be more
tolerant of variation when mapping reads between transcriptomes. The
[Transcriptome Distance Calculator](#transcriptome-distance-calculator) below
will tell you what that threshold should be.

### Usage

```bash
corset-tools cross-count \
  -X transcripts_X.fa \
  -Y transcripts_Y.fa \
  -x SetX_Label \
  -y SetY_Label \
  -c clusters.txt \
  -o outfile.tab
```

### Options

```code
-X, --transFastaX   Fasta file for transcriptome X.

-Y, --transFastaY   Fasta file for transcriptome Y.

-x, --transNameX    Unique label for transcriptome X.
                    Default: the fasta file's base name.

-y, --transNameY    Unique label for transcriptome Y.
                    Default: the fasta file's base name.

-c, --clustMap      Corset transcript-to-cluster mapping file.

-o, --outFile       Output count table. Default: CountClusterMembers.txt

-h, --help          Show help message and exit.
```

Transcript names must be unique across the two transcriptomes; a name appearing
in both makes the membership counts ambiguous and is reported as an error.

## Transcriptome Distance Calculator

When using Corset to cluster transcriptomes from two different
isolates/individuals/cultivars/species, natural sequence variation is likely to
occur between input datasets. For equivalent transcripts to cluster correctly it
is essential that reads are able to cross-map to their equivalent location in
the non-self transcriptome.

In Bowtie2, the minimum score for a 'valid' read alignment is set via the
`--score-min` option. The format is `[type,intercept,slope]`, with the default
setting `-L,-0.6,-0.6`.

The equation for a 100 bp read would be `-0.6 + (-0.6 * 100) = -60.6`.

The default Bowtie2 penalty for a mismatched base is -6. An alignment gap of
length 2 receives a penalty of -11 by default (-5 for the gap open, -3 for the
first extension, -3 for the second extension).

Therefore a 100 bp read alignment is still considered valid with 5 mismatches
(`-6 * 5 = -30`), or one gap plus one mismatch (`-6 + (-5 + -3) = -14`).

Failing to set a minimum score threshold that is below (more negative than) the
expected distance between homologous transcripts will likely result in
transcript clusters that split by source transcriptome; or, if homologous
clusters are predicted, lower mapping efficiency between sets may create a false
differential expression signal in later analyses (genes that are more variable
between two isolates may appear to be differentially expressed when exposed to
the same treatment condition).

Conversely, setting `--score-min` too high will likely result in excessive
collapse of paralogues.

`corset-tools dist-calc` compares equivalent transcript pairs from two
transcriptomes, determines the distance (gaps and mismatches) for each pair, and
reports whether mapping would be successful for a given read length and
`--score-min` setting.

Transcript pairs may be provided as a tab delimited list; alternatively the tool
can perform a reciprocal best BLAST analysis if provided with tab formatted
BLAST results (`-outfmt 6`) for SetA vs SetB, and SetB vs SetA.

Pairs whose lengths differ by more than 50% are excluded, since a global
alignment between them would be dominated by the terminal overhang rather than
by genuine sequence divergence.

### Choosing a `--score-min` threshold

`dist-calc` reports the **minimum alignment score that must be tolerated** in
order to allow cross-mapping for a nominated fraction of the transcript
population (95% by default, set with `-p/--percentile`). It converts that
threshold into a ready-to-paste Bowtie2 setting for your read length, and tells
you whether the `--score-min` you supplied is already permissive enough:

```code
To allow cross-mapping for 95% of transcript pairs (n=412) at readLength=100:
  minimum tolerable alignment score : -48.2
  suggested bowtie2 setting         : --score-min L,11.8,-0.6
  covers                            : 95.4% of pairs
  your current setting              : -60.6 -> covers 98.1% of pairs (sufficient)
```

The threshold is taken from the lower tail of the observed read-penalty
distribution and snapped to an observed value rather than interpolated, so the
recommendation always achieves _at least_ the requested coverage. The slope is
held fixed at whatever you passed to `-s/--scoreMinSlope`, and the intercept is
solved for; a positive intercept simply means your reads can tolerate a
threshold more permissive than the linear default provides at that length.

The distribution itself is written to `-f/--outFig` as a histogram with a fitted
normal curve and the recommended threshold marked.

### Usage

Pairs provided:

```bash
corset-tools dist-calc \
  -r 100 -i -0.6 -s -0.6 \
  -n pairnames.txt \
  -a FASTA_A.fa -b FASTA_B.fa \
  -g -5 -e -3 -m -6 \
  -o alignmentStats.txt
```

Get pairs from reciprocal best BLAST:

```bash
corset-tools dist-calc \
  -r 100 -i -0.6 -s -0.6 \
  -x BLAST_AvsB.tab -y BLAST_BvsA.tab \
  -a FASTA_A.fa -b FASTA_B.fa \
  -g -5 -e -3 -m -6 \
  -o alignmentStats.txt -w
```

### Options

```code
-a, --fastaA            Multifasta set A.

-b, --fastaB            Multifasta set B.

-n, --pairNames         Two column tab delimited file containing names for
                        sequences from fastaA and fastaB to be aligned.
                        Takes precedence over the BLAST inputs.

-x, --blastAvB          Blast tab (-outfmt 6) result file for fastaA query
                        against fastaB subject.

-y, --blastBvA          Blast tab (-outfmt 6) result file for fastaB query
                        against fastaA subject.

-r, --readLength        Length of reads intended for mapping to transcriptomes
                        (after quality trimming). Default: 100

-i, --scoreMinIntercept Intercept value for Bowtie2 --score-min function.
                        Default: -0.6

-s, --scoreMinSlope     Slope value for Bowtie2 --score-min function.
                        Default: -0.6

-g, --gapOpen           Penalty for opening a gap. Default: -5

-e, --gapExtend         Penalty for extending a gap. Default: -3

-m, --mismatch          Penalty for a mismatched position. Default: -6

-p, --percentile        Target percentage of transcript pairs that should be
                        able to cross-map. Default: 95

-o, --outFile           Write output table to file.
                        Default: alignmentStats.txt

-f, --outFig            Write the read penalty distribution to this file.
                        Default: readPenaltyDist.pdf

--no-fig                Skip the distribution figure entirely.

-l, --minLen            Minimum BLAST hit length to consider valid. Default: 0

-E, --eVal              Maximum BLAST e-value to consider valid. Default: 0.001

-w, --recipFile         Write reciprocal blast pairs to file. True if flag is
                        set.

-v, --verbose           Write formatted alignments to screen.

--proc                  Number of processes to split the alignment job over.
                        Default: 4

-h, --help              Show help message and exit.
```

### Output

The statistics table has one row per aligned pair:

```code
transNameA  transNameB  align_len  gaps  mismatches  align_score  mean_read_penalty  cross_map
```

`cross_map` is `SUCCESS` when the pair's expected read penalty clears the
`--score-min` implied by `-i` and `-s` at the given read length, and `FAIL`
otherwise.

## edgeR Cluster Summaries

`corset-tools edger-summary` takes an edgeR `topTags` table of differentially
expressed clusters, filters it by FDR / log fold change / rank, annotates each
surviving cluster with the number of members contributed by each input
transcriptome, and harvests any lines mentioning those members from arbitrary
annotation files (BLAST hits, GO terms, KEGG assignments, descriptions, and so
on).

### Usage

```bash
corset-tools edger-summary \
  --infile edgeR_topTags_SetA_1vsSetB_1.csv \
  --clust clusters.txt \
  --seqFiles SetA_transcripts.fa --seqFiles SetB_transcripts.fa \
  --labels SetA --labels SetB \
  --grepme AB_annotdescriptions.txt --grepme AB_kegg.txt \
  --outDir cluster_reports \
  --topx 50 --maxfdr 0.05 --minfc 1 \
  --writeClusters
```

`--seqFiles`, `--labels` and `--grepme` are each repeated once per value. The
number of `--labels` must match the number of `--seqFiles`.

### Options

```code
-i, --infile        edgeR topTags result table.
                    Format: 'ClusterID,logFC,logCPM,LR,PValue,FDR'

--clust             Corset transcript-to-cluster mapping file.

--seqFiles          Fasta of transcript sequences. Repeat once per
                    transcriptome. Names must be unique across all files.

--labels            Label for each --seqFiles entry, in the same order.
                    Repeat once per file.

--grepme            Annotation file to harvest lines from. Repeatable.

-o, --outDir        Output directory. Default: cluster_reports

--maxfdr            Only records at or below this FDR are considered.
                    Default: 0.05

--minfc             Only records at or above this absolute log2 fold change are
                    considered. Default: 1 (a two-fold change)

-x, --topx          Keep only the top x clusters, sorted by FDR.

--writeClusters     Also write member transcripts to one fasta per cluster.

-h, --help          Show help message and exit.
```

### Output

Written into `--outDir`:

- `<infile>_significant_cluster_report.tab` — the filtered DE table with one
  member-count column per label plus a `Totals` column.
- `<annot>_<infile>_significant_cluster_annotation_records.txt` — one file per
  `--grepme` input, with matching lines grouped under a `#ClusterID` header.
- `<ClusterID>.fa` — one fasta per cluster, written only when
  `--writeClusters` is set.
